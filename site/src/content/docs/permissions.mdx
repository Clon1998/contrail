Contrail only reads from AWS unless you allow changes. If your SSO role is an admin or read-only role, you're set
for reading. Teammates
with narrower roles need the permissions below: give the policy to whoever manages your SSO
permission sets.

- **`ContrailReadOnly`**: listing clusters, services, tasks and task definitions, reading log
  events and Live Tail. Without `logs:StartLiveTail` Contrail checks for new events every
  2 seconds instead.
- **`ContrailOptionalRevealSecrets`**: only to reveal secret values of environment variables.
  Narrow its `Resource` to the secrets your team may read. Each read shows up in CloudTrail.
- **`ContrailOptionalInsightsTrace`**: only for "Use Logs Insights" when tracing across many
  services (billed per GB scanned).
- **`ContrailOptionalChanges`**: only for stopping tasks and updating services from Contrail
  (desired count, revision, new deployment), with **Allow changes to AWS** on in the settings.
  Without it, a role can't change anything, whatever the app does.

<Aside type="note" title="No credentials of its own">
  Contrail keeps no credentials of its own. It reads the expiry of the SSO token cache to show whether a
  profile is logged in; its built-in login (used without the AWS CLI) writes the token there, exactly as
  `aws sso login` would. The AWS SDK handles everything else.
</Aside>
